# 장르: announcement (공지/모집)

이벤트, 출시, 모집, 행사 공지.
디스코드 공지, 슬랙 채널 공지, 소셜미디어 이벤트 글 등.

---

## 정의

다음 중 하나에 해당하면 announcement 장르.

- 이벤트 / 행사 안내.
- 제품 / 기능 출시 알림.
- 참여자 모집 (스터디, 베타 테스트, 채용 등).
- 변경 사항 공지 (정책 변경, 일정 변경).
- 마감/시작 알림.

수신자가 액션을 취하길 바라는 글.

---

## 핵심 구조

후킹 + 핵심 정보 + CTA 3부 구조.

### 후킹 (첫 1-2 문장)

- 이 공지가 누구에게 왜 의미 있는지 짧고 명확히.
- 클릭/스크롤을 멈추게 해야 한다.
- "안녕하세요 여러분!" 같은 빈 인사 금지.

### 핵심 정보 (5W1H)

- **What**. 무엇.
- **When**. 언제 (날짜, 시간).
- **Where**. 어디서 (오프라인/온라인 + 링크).
- **Who**. 누구를 대상으로.
- **Why**. 왜 (참여 가치).
- **How**. 어떻게 참여하는지.

### CTA (Call to Action)

- 무엇을 해야 하는지 명확히.
- 링크, 폼, 이메일 등 구체적 경로.
- 마감일 명시.

---

## 톤 / 길이 / 종결어

| 항목 | 가이드 |
|---|---|
| 전체 길이 | 200-500자 |
| 한 단락 | 1-3 문장 |
| 종결어 | ~요 / ~합니다 혼용 |
| 톤 | 친근, 명확, 약간의 임팩트 |
| 이모지 | 1-3개 허용 (장식이 아니라 정보 구분용) |
| 줄바꿈 | 적극 활용. 모바일 가독성 |

---

## 장르 특수 안티패턴

공통 안티패턴 외에 announcement 장르에서 특히 조심할 것.

| 패턴 | 왜 금지 |
|---|---|
| "안녕하세요 여러분!" | 빈 인사. 본론 직진 |
| "정말 기쁜 소식이에요!" | 클리셰. 무엇이 기쁜지로 직접 |
| "많은 관심 부탁드립니다" | 빈 권유. 구체적 CTA로 |
| "놓치지 마세요!" | 광고 톤 클리셰 |
| 이모지 5개 이상 | 진지함 떨어짐. 정보 가려짐 |
| 과도한 ✨🎉🚀 | 마케팅 톤 과잉 |
| 5W1H 누락 | 정보 부족으로 액션 불가 |
| CTA 모호 | "관심 있으신 분은 댓글 주세요" 같은 약한 CTA |

## 공지 유형별 템플릿

### 이벤트 / 모집

```
[후킹 첫 줄: 이 이벤트가 누구에게 왜 의미 있는지]

[2-3 줄: 무엇을 하는 이벤트인지]

📅 일시: YYYY년 MM월 DD일 (요일) HH:MM
📍 장소: [장소 또는 온라인 링크]
👥 대상: [구체적 대상]
📌 인원: N명 (선착순 / 추첨)

[참여 방법: 링크 또는 폼]

신청 마감: MM월 DD일 (요일) HH:MM
```

### 출시 / 변경 공지

```
[후킹 첫 줄: 무엇이 새로 나왔는지 / 무엇이 바뀌었는지]

[2-3 줄: 핵심 내용]

✅ 변경 내용:
- 항목 1
- 항목 2
- 항목 3

[시행 시점: YYYY년 MM월 DD일부터]

[확인 방법: 링크 또는 위치]
```

### 마감 알림

```
[후킹: 무엇의 마감이 임박했는지]

마감: MM월 DD일 (요일) HH:MM (D-N일 남음)

[놓치면 안 되는 이유]

[참여/완료 링크]
```

## Before / After

### Before (이벤트 공지)

```
@everyone 안녕하세요 여러분! 정말 기쁜 소식이에요 🎉🎉🎉

이번에 우리가 정말 멋진 마케팅 팟캐스트를 준비했어요!! 
PMF 검증부터 마케팅 전략까지 — 정말 많은 인사이트를 얻으실 수 있을 거예요 ✨

여러분이 평소에 궁금하셨던 모든 것들을 함께 이야기 나누는 시간이 될 것 같아요. 
많은 관심 부탁드려요! 놓치지 마세요! 🚀

자세한 내용은 아래 링크에서 확인하실 수 있습니다 :)
```

### After

```
@everyone

사이드 프로젝트 하면서 한 번쯤 겪는 막막함을 같이 풀어볼 자리입니다.

📅 일시: 6월 15일 (토) 20:00
📍 장소: 온라인 (디스코드 음성 채널)
👥 대상: 사이드 프로젝트 만들고 있는 누구나

같이 생각해볼 것들
- 내 제품이 잘 되고 있는 건지, 어떻게 알 수 있을까요?
- 유저를 늘리기 전에 먼저 봐야 할 게 있을까요?
- 돈도 없고 채널도 없을 때, 첫 유저는 어디서 올까요?

사전 질문이 있다면 댓글에 남겨주세요.
세션에서 직접 다뤄볼게요.

신청 링크: [링크]
```

## 디스코드 특화 가이드

디스코드 공지는 추가 고려사항이 있다.

- `@everyone` / `@here` 적절히 사용 (남발 금지).
- 마크다운 활용 (`# 제목`, `**굵게**`, `> 인용`).
- 줄바꿈 적극 활용. 모바일 사용자 많음.
- 이모지는 정보 구분용으로만 (📅📍👥📌 같은 위치 표시).
- 너무 긴 공지는 접힘 처리되므로 핵심을 위로.

## 체크리스트

announcement 장르 완료 후 확인.

- [ ] 첫 문장이 후킹 (빈 인사 없음)
- [ ] 5W1H 모두 명시 (이벤트의 경우)
- [ ] 날짜와 시간이 구체적 (요일 포함)
- [ ] CTA가 명확 (어디로, 무엇을, 언제까지)
- [ ] 마감일이 명시되어 있음
- [ ] 이모지 정보 구분용 1-3개 (장식용 금지)
- [ ] 전체 200-500자
- [ ] "많은 관심", "놓치지 마세요" 같은 빈 권유 0건
- [ ] 줄바꿈으로 모바일 가독성 확보
