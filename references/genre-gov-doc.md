# 장르: gov-doc (거버넌스 문서)

제안서, 정책서, 의사결정 문서, 분석 보고서, 회고 문서.
조직의 결정과 정책을 기록하는 공식 문서.

---

## 정의

다음 중 하나에 해당하면 gov-doc 장르.

- **의사결정 문서 (Decision Doc).** 무엇을 결정했고, 왜 그렇게 결정했는지.
- **정책/프로세스 문서.** 어떻게 일해야 하는지 정의.
- **전략 문서.** 방향과 우선순위.
- **회고/분석 문서.** 무엇을 배웠는지.
- **공공 정책 제안서.** 시민 참여형 제안 포함.

핵심 특징: **6개월 후 다른 사람이 읽어도 완전히 이해 가능해야 한다.**

---

## 핵심 구조

문서 유형마다 구조가 다르다.

### 의사결정 문서

```
1. 요약 (TL;DR)
2. 배경 / 맥락
3. 검토한 옵션
4. 선택한 옵션 + 이유
5. 예상 영향 / 리스크
6. 일정 / 책임자
```

### 정책/프로세스 문서

```
1. 목적 (왜 이 정책이 있는가)
2. 적용 범위 (누구에게, 언제)
3. 정책 내용
4. 예외 사항
5. 위반 시 처리
6. 개정 이력
```

### 전략 문서

```
1. 비전 / 목표
2. 현황 분석
3. 핵심 가설
4. 전략 방향
5. 실행 계획
6. 측정 지표
```

### 회고/분석 문서

```
1. 요약 (3-5줄)
2. 무엇이 일어났는가
3. 무엇이 잘 됐는가
4. 무엇이 안 됐는가
5. 배운 것
6. 다음에 다르게 할 것
```

### 공공 정책 제안서

```
1. 문제 정의
2. 영향 받는 시민 / 규모
3. 현행 제도의 한계
4. 제안 내용
5. 예상 효과
6. 예상 비용 / 시행 일정
```

---

## 톤 / 길이 / 종결어

| 항목 | 가이드 |
|---|---|
| 전체 길이 | 길어도 OK. 정보 밀도가 중요 |
| 한 단락 | 3-5 문장 |
| 종결어 | ~다 / ~한다 (단정형). ~합니다는 부적합 |
| 톤 | 객관적, 분석적, 단정적 |
| 인칭 | 1인칭 단수("나") 회피. "본 제안은", "조직은" 등 객관 주어 |
| 도표 | 표, 다이어그램 적극 활용 |

---

## 장르 특수 안티패턴

공통 안티패턴 외에 gov-doc 장르에서 특히 조심할 것.

| 패턴 | 왜 금지 |
|---|---|
| "~할 것 같다", "~인 듯하다" | 근거 부재. 단정 또는 데이터 인용으로 |
| "많은", "다양한", "여러" | 구체적 숫자나 항목으로 |
| "필요하다고 사료됩니다" | 빈 격식. "필요하다" 로 직접 |
| "~의 일환으로" | 영어 calque ("as part of") |
| "~에 있어" | 한국어로 부자연. 삭제하거나 다른 표현 |
| 약어 정의 없이 사용 | 6개월 후 못 읽음. 첫 사용 시 정의 |
| 결론만 있고 근거 없음 | 의사결정 문서 자격 미달 |
| 옵션 분석 없이 결론만 | 다른 옵션을 왜 안 골랐는지 모름 |

## 핵심 작성 원칙

### 1. 맥락 내장

이 문서를 처음 보는 사람도 이해할 수 있어야 한다.

❌ "이번 분기에 검색 알고리즘을 ML 기반으로 변경하기로 했다."
✅ "현재 검색 알고리즘은 키워드 매칭 기반이다. 지난 분기 사용자 만족도 조사에서 검색 결과 관련성이 4.2/10으로 가장 낮은 점수를 기록했다. 이 문제를 해결하기 위해 다음 분기부터 ML 기반 검색 알고리즘으로 전환한다."

### 2. 구체적 근거

모든 주장에는 근거. 모든 수치에는 출처.

❌ "사용자 이탈률이 높다."
✅ "사용자 이탈률은 2026년 3월 기준 27%로, 동종업계 평균(15%)을 12%p 상회한다." (출처: 2026 Q1 분석 리포트)

### 3. 옵션 분석

결정 문서는 다른 옵션을 왜 안 골랐는지 보여야 한다.

```
| 옵션 | 장점 | 단점 | 예상 비용 |
|---|---|---|---|
| A. 현행 유지 | 추가 비용 0 | 이탈률 개선 안 됨 | - |
| B. ML 전환 | 정확도 30% 개선 예상 | 6개월 + 2억 | 2억 |
| C. 외부 API | 빠른 도입 | 의존성, 월 500만원 | 6,000만/년 |

선택: B
이유: 장기 ROI가 가장 높고, 사용자 만족도 개선이 가장 큰 폭으로 예상됨.
```

### 4. 약어 정의

전문 용어와 약어는 첫 사용 시 정의.

❌ "DAU가 하락했다."
✅ "일간 활성 사용자(DAU, Daily Active Users)가 하락했다."

### 5. 위험과 한계 명시

리스크와 가정의 한계를 명시.

```
리스크
- ML 모델 학습에 필요한 데이터가 부족할 수 있음
- 전환 기간 동안 일시적 성능 저하 가능

가정
- 사용자 행동 데이터 수집 동의율이 현 수준(70%) 유지
- 데이터 사이언티스트 채용이 2026년 상반기에 완료
```

## Before / After

### Before (의사결정 문서)

```
검색 알고리즘 변경 건

기본적으로 우리 팀은 검색 시스템에 어떤 문제가 있다고 판단했고, 
이 부분을 개선하기 위해 다양한 옵션을 검토했습니다. 결국에는 ML 기반으로 
가는 것이 좋겠다는 결론에 도달했어요. 다른 옵션들도 있었지만, 본질적으로 
ML이 가장 적절하다고 봅니다. 실행은 빠른 시일 내에 시작할 예정입니다.
```

### After

```
# 검색 알고리즘 ML 기반 전환 결정

## 요약

검색 알고리즘을 키워드 매칭 기반에서 ML 기반으로 전환한다.
전환 기간 6개월, 예상 비용 2억 원.
1차 출시 목표: 2026년 12월.

## 배경

현재 검색 알고리즘은 키워드 매칭 기반이다.
2026년 Q1 사용자 만족도 조사에서 검색 결과 관련성은 4.2/10이었다.
전체 기능 중 가장 낮은 점수다.

검색을 통한 구매 전환율은 8%로, 카테고리 탐색 전환율(23%)의 1/3 수준이다.
이 격차가 분기 매출 손실로 환산 시 약 3.2억 원으로 추산된다.

## 검토한 옵션

| 옵션 | 장점 | 단점 | 예상 비용 |
|---|---|---|---|
| A. 현행 유지 | 추가 비용 0 | 매출 손실 지속 | - |
| B. ML 전환 | 정확도 30% 개선 예상, 장기 ROI | 6개월, 2억 | 2억 |
| C. 외부 API | 1개월 도입 가능 | 월 500만 의존성, 데이터 외부 유출 | 6,000만/년 |

## 선택: B (ML 전환)

이유:
- 1년차 손익분기 (2억 투자, 예상 매출 회복 3.2억)
- 검색 데이터 내재화로 장기 자산화
- 외부 API 대비 데이터 보안 우위

## 일정

- 2026년 7월: 데이터 파이프라인 구축
- 2026년 10월: 모델 학습 완료
- 2026년 12월: 1차 출시 (전체 트래픽의 10% A/B 테스트)
- 2027년 3월: 전체 전환 검토

## 리스크

- ML 모델 학습 데이터가 부족할 수 있음. 대응: 외부 데이터셋 일부 활용 검토.
- 전환 기간 일시적 성능 저하 가능. 대응: A/B 테스트로 점진 전환.

## 책임자

- 프로젝트 리드: PM
- 기술 리드: AI팀 김OO
- 검토 위원: CTO, CPO
```

- [ ] 맥락이 문서 내에 내장되어 있는가

- [ ] 옵션 분석이 있는가 (의사결정 문서면)
