# 장르: report (기술 / 리포트)

분석 보고서, PRD, 기술 문서, 회의록.
정보 전달과 정확성이 최우선인 문서.

---

## 정의

다음 중 하나에 해당하면 report 장르.

- **분석 보고서.** 데이터 분석, 사용자 행동, 시장 분석.
- **PRD (Product Requirements Document).** 제품 기획.
- **기술 문서.** 아키텍처, API, 시스템 설계.
- **회의록.** 결정 사항, 액션 아이템.
- **주간/월간 보고.** 진행 상황 요약.

특징: **객관적 사실 + 구체적 수치 + 명확한 구조**.

---

## 핵심 구조

문서 유형마다 조금 다르지만 공통 패턴이 있다.

### 분석 보고서

```
1. 요약 (Executive Summary) - 3-5줄
2. 배경 / 분석 목적
3. 분석 방법론
4. 핵심 발견 (Key Findings)
5. 세부 분석
6. 결론 / 권장 사항
7. 부록 (데이터, 차트)
```

### PRD

```
1. 개요
2. 문제 정의
3. 사용자 / 시장
4. 목표 / 성공 지표
5. 요구사항 (Functional / Non-functional)
6. 와이어프레임 / 흐름도
7. 일정 / 마일스톤
8. 리스크 / 의존성
```

### 회의록

```
1. 기본 정보 (일시, 참석자, 주제)
2. 논의 사항
3. 결정 사항
4. 액션 아이템 (담당자 + 기한)
5. 다음 회의
```

### 주간 / 월간 보고

```
1. 한 줄 요약
2. 주요 진척 사항
3. 이슈 / 블로커
4. 다음 기간 계획
5. 지표 변화
```

---

## 톤 / 길이 / 종결어

| 항목 | 가이드 |
|---|---|
| 전체 길이 | 길어도 OK. 정보 밀도 우선 |
| 한 단락 | 3-5 문장 |
| 종결어 | ~다 / ~한다 (단정형) |
| 톤 | 객관적, 분석적, 사실 중심 |
| 인칭 | 1인칭 회피. "본 보고서", "분석 결과" 등 객관 주어 |
| 차트 / 표 | 적극 활용 |

---

## 장르 특수 안티패턴

공통 안티패턴 외에 report 장르에서 특히 조심할 것.

| 패턴 | 왜 금지 |
|---|---|
| "~할 것으로 사료된다" | 빈 격식. 단정 또는 데이터 인용 |
| "다양한 인사이트" | 구체적 인사이트가 아니라는 신호 |
| "깊이 있는 분석" | 클리셰. 실제 분석이 부재할 가능성 |
| "전반적으로" | 빈 부사. 구체적 범위로 |
| "기대된다" | 추측. 데이터 기반 예측으로 |
| 수치 없는 주장 | report 자격 미달 |
| 차트 없이 텍스트만 | 가독성 저하 |
| 발견과 권장이 섞임 | 사실과 의견 분리 필요 |

## 핵심 작성 원칙

### 1. 사실과 해석 분리

객관적 사실과 글쓴이의 해석을 명확히 구분.

❌ "사용자 이탈률이 27%로 매우 높았다."
✅ "사용자 이탈률은 27%였다. 이는 동종업계 평균(15%) 대비 12%p 높은 수치다." (사실)
   "이 격차의 주요 원인은 온보딩 7단계 중 4단계에서의 이탈로 보인다." (해석)

### 2. 모든 수치에 단위와 출처

❌ "사용자가 증가했다."
✅ "월간 활성 사용자(MAU)가 2026년 1월 12만 명에서 3월 18만 명으로 50% 증가했다." (출처: Amplitude 대시보드, 2026 Q1)

### 3. 핵심 발견을 위로

요약을 맨 위에. 바쁜 독자도 첫 5줄에서 핵심을 알 수 있어야 한다.

```
요약
- 이탈률 27%로 업계 평균 대비 12%p 높음
- 주요 이탈 지점: 온보딩 4단계 (전체 이탈의 62%)
- 권장: 4단계 간소화 또는 5단계 통합
```

### 4. 표와 차트 적극 활용

긴 텍스트보다 표가 빠르다.

```
| 단계 | 진입 사용자 | 다음 단계 진입 | 이탈률 |
|---|---|---|---|
| 1. 회원가입 | 10,000 | 8,500 | 15% |
| 2. 이메일 인증 | 8,500 | 7,800 | 8% |
| 3. 프로필 입력 | 7,800 | 6,200 | 21% |
| 4. 결제 정보 입력 | 6,200 | 2,800 | 55% |
| 5. 완료 | 2,800 | - | - |
```

### 5. 액션 아이템 명시

분석으로 끝나면 안 된다. 다음 단계가 있어야 한다.

```
권장 액션
1. 결제 정보 입력 단계 간소화 (담당: 디자인팀, 기한: 4/30)
2. 4단계 사용자 인터뷰 10건 진행 (담당: PM, 기한: 4/15)
3. A/B 테스트 설계 (담당: 데이터팀, 기한: 5/15)
```

## Before / After

### Before (분석 보고서)

```
사용자 행동 분석 결과 보고

본 보고서는 기본적으로 우리 팀이 지난 분기 동안 진행한 사용자 행동 분석의 
결과를 정리한 것입니다 — 결국에는 다양한 인사이트가 도출되었으며, 이러한 
결과는 향후 제품 개발에 있어 매우 중요한 의미를 가집니다. 본질적으로 
사용자들이 우리 서비스를 어떻게 사용하는지에 대한 깊이 있는 이해를 
제공해드릴 수 있을 것으로 기대됩니다.

전반적으로 사용자 이탈률이 높은 편이며, 특히 결제 단계에서 많은 사용자가 
이탈하는 경향을 보였습니다. 이에 대한 개선이 필요할 것으로 사료됩니다.
```

### After

```
# 사용자 행동 분석 보고서 (2026 Q1)

## 요약

- 전체 이탈률 27% (동종업계 평균 15% 대비 12%p 높음)
- 주요 이탈 지점: 온보딩 4단계 결제 정보 입력 (전체 이탈의 62%)
- 권장: 결제 정보 입력 단계 간소화 + 4단계 사용자 인터뷰

## 분석 개요

- 기간: 2026년 1월 1일 ~ 3월 31일
- 대상: 신규 가입자 10,000명
- 도구: Amplitude, Mixpanel

## 핵심 발견

### 1. 단계별 이탈률

| 단계 | 진입 사용자 | 이탈 사용자 | 이탈률 |
|---|---|---|---|
| 1. 회원가입 | 10,000 | 1,500 | 15% |
| 2. 이메일 인증 | 8,500 | 700 | 8% |
| 3. 프로필 입력 | 7,800 | 1,600 | 21% |
| 4. 결제 정보 입력 | 6,200 | 3,400 | 55% |
| 5. 완료 | 2,800 | - | - |

4단계 이탈률 55%는 다른 단계 대비 2.5배 이상이다.

### 2. 이탈 원인 (사용자 인터뷰 8건)

- "결제 정보를 미리 받는 게 부담" (5건)
- "어떤 기능을 쓸지 모르는데 결제부터 요구" (4건)
- "다른 서비스는 무료 체험 후 결제하는데" (3건)

## 권장 액션

| 액션 | 담당 | 기한 |
|---|---|---|
| 결제 정보 입력 단계 간소화 검토 | 디자인팀 | 2026-04-30 |
| 4단계 사용자 인터뷰 10건 추가 | PM | 2026-04-15 |
| 결제 단계 A/B 테스트 설계 | 데이터팀 | 2026-05-15 |

## 부록

- 데이터 출처: Amplitude 대시보드 (링크)
- 사용자 인터뷰 노트 (링크)
- 동종업계 벤치마크 (링크)
```

## 체크리스트

report 장르 완료 후 확인.

- [ ] 첫 5줄에서 핵심 발견을 파악할 수 있는가 (요약)
- [ ] 모든 수치에 단위와 출처가 있는가
- [ ] 사실과 해석이 분리되어 있는가
- [ ] 표/차트를 적절히 사용했는가
- [ ] 권장 액션에 담당자와 기한이 있는가
- [ ] 종결어가 ~다 (단정형)
- [ ] 1인칭 회피했는가
- [ ] "사료된다", "기대된다" 같은 빈 격식 0건
- [ ] "다양한", "많은", "전반적으로" 같은 빈 표현 0건
- [ ] 약어 첫 사용 시 정의했는가
