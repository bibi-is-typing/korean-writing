# 장르: blog (블로그/에세이)

깊은 인사이트, 본인 분석, 경험 공유를 위한 글.
1,500자 이상의 본격적인 글.

---

## 정의

다음 중 하나에 해당하면 blog 장르.

- 본인의 깊은 분석이나 관점을 담은 글.
- 경험에서 얻은 인사이트를 보편화한 글.
- 특정 주제에 대한 체계적인 설명.
- 자기소개 에세이, 회고록, 사례 연구.

링크드인 포스트보다 길고, 리포트보다 개인적인 글.

---

## 핵심 구조

도입 + 본론 + 결론 3부 구조.

### 도입

- 첫 문장은 흡인력 있는 문제 제기 또는 단정.
- "오늘은 ~에 대해 이야기해보려 합니다" 같은 클리셰 도입 금지.
- 2-4 문장 안에 글의 주제와 방향을 명확히.

### 본론

- 3-5개의 H2 (##) 섹션으로 구성.
- 각 섹션은 3-5 단락.
- 주장 → 근거 → 사례 → 소결 순서.
- 구체적 수치, 사례, 본인 경험을 포함.

### 결론

- H2 사용하지 않음. 자연스러운 마지막 단락.
- 1-2 단락.
- 다음 행동 또는 더 큰 질문으로 마무리.

---

## 톤 / 길이 / 종결어

| 항목 | 가이드 |
|---|---|
| 전체 길이 | 1,500-3,500자 |
| 한 단락 | 3-5 문장 |
| 종결어 | ~예요/요 (구어체) 우세, ~합니다 일부 혼용 |
| 톤 | 사색적, 약간 격식, 개인적 |
| 첫 문장 | 단정 또는 도발적 문제 제기 |
| 마지막 문장 | 다음 행동 또는 더 큰 질문 |

---

## 장르 특수 안티패턴

공통 안티패턴 외에 blog 장르에서 특히 조심할 것.

| 패턴 | 왜 금지 |
|---|---|
| "오늘은 ~에 대해 이야기해보려 합니다" | 클리셰 도입. 정보 없음 |
| "여러분도 한 번쯤 ~한 경험이 있으실 거예요" | 빈 공감 유도 |
| "지금까지 ~에 대해 알아봤습니다" | 클리셰 마무리. 정보 없음 |
| "어떻게 생각하시나요?" | 빈 질문. 의미 없는 인터랙션 유도 |
| 과도한 H3, H4 사용 | 에세이가 아니라 리포트 같아짐 |
| 인용구만 잔뜩 | 본인 분석이 약함의 신호 |

### Before

```
안녕하세요 여러분! 오늘은 PMF 검증이라는 주제에 대해 이야기해보려고 합니다.
PMF는 정말 중요한 개념인데요 — 기본적으로 모든 스타트업이 한 번쯤 겪게 되는
고민이라고 할 수 있죠. 여러분도 한 번쯤은 이런 경험이 있으실 거예요.

PMF를 검증하는 방법은 여러 가지가 있습니다. 그중에서 가장 중요한 것은
사용자의 반응을 측정하는 것이라고 할 수 있어요. 어떻게 측정해야 할까요?

(중략)

지금까지 PMF 검증에 대해 알아봤습니다. 여러분도 잘 활용해보시기 바랍니다.
어떻게 생각하시나요?
```

```
PMF 검증의 가장 흔한 실수는 검증 도구가 아니라 검증 목적이 헷갈리는 것입니다.

팀 합의용 검증과 시장 검증용 검증은 완전히 다른 설계가 필요해요.
그런데 많은 팀이 이 둘을 구분하지 않고 시작합니다.
그러다 데이터가 나오면 각자 다르게 해석하고, 회의는 누가 더 잘 설득하느냐
싸움이 됩니다.
```

- [ ] 첫 문장이 클리셰 도입이 아님
- [ ] 도입이 4 문장 이내
- [ ] H2 섹션 3-5개
- [ ] 각 H2 아래 3-5 단락
- [ ] 결론에 H2 사용 안 함
- [ ] 마지막에 "어떻게 생각하시나요" 같은 빈 질문 없음
- [ ] 전체 1,500-3,500자
- [ ] 구체적 사례나 수치 최소 3건
- [ ] 종결어가 ~예요/요 우세
