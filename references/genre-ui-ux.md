# 장르: ui-ux (UI/UX 라이팅)

버튼, 에러 메시지, 토스트, 툴팁, 온보딩, 빈 상태 등 제품 인터페이스 안의 모든 텍스트.
짧고, 명확하고, 행동을 유도하는 글.

---

## 정의

다음 중 하나에 해당하면 ui-ux 장르.

- 버튼, CTA, 탭, 메뉴 레이블.
- 에러 메시지, 확인 다이얼로그, 토스트/스낵바.
- 툴팁, 플레이스홀더, 헬프 텍스트.
- 온보딩 스텝, 빈 상태(Empty State), 로딩 메시지.
- 랜딩 페이지 헤드카피, 서브카피.
- 디스코드 봇 메시지, 알림 문구.

블로그보다 짧고, 공지보다 기능에 밀착된 글.

---

## 핵심 원칙 (UI/UX 전용 7가지)

### 1. 행동 우선 (Action-First)

사용자가 할 수 있는 행동부터 쓴다. 설명이 먼저 오면 안 된다.

| Before | After |
|---|---|
| "이 기능은 파일을 업로드할 수 있게 해줍니다" | "파일 업로드" |
| "삭제를 원하시면 아래 버튼을 눌러주세요" | "삭제하기" |
| "설정이 저장되었습니다. 확인 버튼을 눌러주세요" | "저장 완료" |

### 2. 주어는 시스템이 아니라 사용자

시스템이 한 일이라도, 사용자 관점에서 쓴다.

| Before | After |
|---|---|
| "저희가 이메일을 보내드렸습니다" | "인증 메일이 도착했어요" |
| "서버에서 오류가 발생했습니다" | "잠시 문제가 생겼어요. 다시 시도해 주세요" |
| "시스템이 처리 중입니다" | "처리 중이에요" |

### 3. 공포 유발 금지 (Fear-Free Error)

에러 메시지에서 사용자를 겁주지 않는다. 원인 + 해결을 함께 준다.

| Before | After |
|---|---|
| "치명적 오류가 발생했습니다!" | "문제가 생겼어요. 다시 시도하면 됩니다" |
| "잘못된 입력입니다" | "이메일 형식을 확인해 주세요" |
| "권한이 없습니다" | "이 작업은 관리자만 할 수 있어요" |
| "404 Not Found" | "페이지를 찾지 못했어요" |

### 4. 글자 수 제한 (Brevity Budget)

| UI 요소 | 최대 글자 수 (한국어 기준) |
|---|---|
| 버튼 | 8자 |
| 토스트/스낵바 | 20자 |
| 툴팁 | 30자 |
| 빈 상태 (Empty State) | 2줄 (행동 1개 포함) |
| 에러 메시지 | 원인 1줄 + 해결 1줄 |
| 온보딩 스텝 | 제목 10자 + 설명 30자 |
| 랜딩 헤드카피 | 15자 |
| 랜딩 서브카피 | 40자 |

글자 수를 넘기면 문장이 아니라 정보를 줄인다.

### 5. 일관된 동사 체계

같은 행동에 같은 동사를 쓴다. 섞으면 인지 부하가 생긴다.

| 행동 | 통일 동사 | 혼용 금지 |
|---|---|---|
| 만들기 | "만들기" 또는 "새로 만들기" | 생성, 추가, 작성 혼용 |
| 지우기 | "삭제" | 제거, 지우기, 없애기 혼용 |
| 고치기 | "수정" | 편집, 변경, 업데이트 혼용 |
| 보내기 | "보내기" | 전송, 발송, 송신 혼용 |
| 저장 | "저장" | 보관, 기록 혼용 |
| 취소 | "취소" | 되돌리기, 철회 혼용 |

제품 전체에서 동사 테이블을 하나 정해놓고 지킨다.

### 6. 존댓말 레벨 통일

한 제품 안에서 존댓말 레벨이 흔들리면 안 된다. 하나만 고르고 전체에 적용.

| 레벨 | 톤 | 적합한 제품 |
|---|---|---|
| 해요체 | "저장했어요", "삭제할까요?" | 일반 B2C, 모바일 앱 |
| 합쇼체 | "저장되었습니다", "삭제하시겠습니까?" | B2B, 금융, 관공서 |
| 반말 | "저장됨", "삭제할까?" | 개발 도구, 내부 툴 |

혼용 예시 (금지): "저장되었습니다" (합쇼체) + "다시 해볼래요?" (해요체)

### 7. 빈 상태는 행동을 준다 (Empty State = Next Action)

빈 화면에 상태만 알리면 막다른 길이다. 다음 행동을 함께 준다.

| Before | After |
|---|---|
| "데이터가 없습니다" | "아직 프로젝트가 없어요. 첫 프로젝트를 만들어 보세요" + [만들기] 버튼 |
| "검색 결과가 없습니다" | "결과가 없어요. 다른 키워드로 검색해 보세요" |
| "알림이 없습니다" | "새 알림이 없어요" |

## 톤 / 길이 / 종결어

| 항목 | 가이드 |
|---|---|
| 전체 길이 | UI 요소별 글자 수 제한 참고 |
| 한 문장 | 1문장 원칙. 최대 2문장 |
| 종결어 | 제품의 존댓말 레벨에 따라 통일 |
| 톤 | 명확, 간결, 친절 (과하지 않게) |
| 감정 표현 | 성공: 담백하게. 에러: 안심시키며. 경고: 명확하게 |

## UI 요소별 패턴

### 버튼 / CTA

- 동사로 시작. "저장하기", "삭제", "보내기".
- 명사형도 가능. "다음", "완료", "취소".
- "확인"은 모호하다. 무엇을 확인하는지 명시. "삭제", "저장", "보내기".

### 에러 메시지

구조: 원인 1줄 + 해결 1줄.

```
비밀번호가 일치하지 않아요.
다시 입력해 주세요.
```

```
네트워크 연결이 끊겼어요.
Wi-Fi 상태를 확인해 주세요.
```

### 토스트 / 스낵바

- 20자 이내 1줄.
- 동작 결과만 알린다. "저장했어요", "복사했어요", "삭제했어요".
- 실패 시 해결 동작 링크 포함. "저장 실패. [다시 시도]"

### 빈 상태 (Empty State)

구조: 상태 1줄 + 행동 유도 1줄 + CTA 버튼.

```
아직 프로젝트가 없어요.
첫 프로젝트를 만들어 보세요.
[새 프로젝트 만들기]
```

### 온보딩 스텝

구조: 제목 (10자) + 설명 (30자) + CTA.

```
제목: 팀원 초대
설명: 함께 작업할 팀원의 이메일을 입력하세요.
CTA: [초대하기]
```

### 확인 다이얼로그

구조: 질문 1줄 + 결과 설명 (필요시) + 버튼 2개.

```
이 프로젝트를 삭제할까요?
삭제하면 되돌릴 수 없어요.
[취소] [삭제]
```

파괴적 행동의 버튼은 행동을 명시한다. "확인" 대신 "삭제".

## 장르 특수 안티패턴

공통 안티패턴 외에 ui-ux 장르에서 특히 조심할 것.

| 패턴 | 왜 금지 |
|---|---|
| "확인" 버튼 (맥락 없이) | 무엇을 확인하는지 모호. "저장", "삭제", "보내기"로 명시 |
| "오류가 발생했습니다" (해결 없이) | 사용자가 할 수 있는 게 없다. 해결 행동을 함께 제시 |
| "~해주세요" 남발 | 모든 문장이 부탁이 되면 톤이 무너진다. 핵심 CTA에만 사용 |
| 시스템 용어 노출 | "null", "undefined", "500 error", "timeout" 등 사용자에게 의미 없는 기술 용어 |
| 이중 부정 | "취소하지 않으시겠습니까?" → "계속할까요?" |
| 존댓말 레벨 혼용 | 한 화면에 합쇼체와 해요체가 섞이면 톤이 흔들린다 |
| 긴 설명문 | 3문장 이상의 안내문. UI에서는 1-2문장이 한계 |

## Before / After

### Before

```
[팝업]
오류가 발생하였습니다.
시스템에서 예기치 않은 오류가 발생했습니다.
확인 버튼을 눌러 다시 시도해 주세요.
[확인]

[빈 상태]
데이터가 없습니다.

[버튼들]
생성  |  편집하기  |  제거  |  전송

[토스트]
데이터가 성공적으로 저장되었습니다!
```

### After

```
[팝업]
문제가 생겼어요.
다시 시도해 주세요.
[다시 시도]

[빈 상태]
아직 프로젝트가 없어요.
첫 프로젝트를 만들어 보세요.
[만들기]

[버튼들]
만들기  |  수정  |  삭제  |  보내기

[토스트]
저장했어요.
```

## 체크리스트

ui-ux 장르 완료 후 확인.

- [ ] 버튼 텍스트 8자 이내
- [ ] 에러 메시지에 해결 행동 포함
- [ ] 빈 상태에 다음 행동 포함
- [ ] 존댓말 레벨이 전체에서 통일
- [ ] 같은 행동에 같은 동사 사용 (동사 테이블 일관성)
- [ ] "확인" 버튼 없이 구체적 행동 명시
- [ ] 시스템 용어 노출 0건
- [ ] 이중 부정 0건
- [ ] 3문장 이상 안내문 0건
- [ ] 토스트 20자 이내
- [ ] 툴팁 30자 이내
